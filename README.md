# Missing Alert Care

> 실종경보가 발령되는 순간, 사용자가 일반 안전안내와 명확하게 구분해 인식하고 실종자의 특징을 기억하여 제보할 수 있도록 돕는 라이프케어 서비스
> 

## 프로젝트 소개

`Missing Alert Care`는 실종경보가 발령됐을 때 일반 안전안내와 구분되는 전용 푸시 알림을 제공하는 서비스입니다.

현재 실종경보는 다른 안전안내와 유사한 형태로 전달되기 때문에 사용자가 경보의 중요성을 즉시 인식하기 어렵고, 실종자의 사진이나 인상착의를 충분히 기억하지 못할 수 있습니다.

본 프로젝트는 실종자의 사진, 옷차림, 신체 특징, 마지막 목격 장소를 사용자가 빠르게 확인할 수 있도록 정보를 재구성하고, 목격 시 182 전화 또는 제보 행동으로 연결하는 것을 목표로 합니다.

## 개발 배경

실종자를 신속하게 발견하기 위해서는 사건 초기 시민의 관심과 제보가 중요합니다. 하지만 현재의 문자 중심 경보는 다음과 같은 한계가 있습니다.

- 일반 안전안내와 실종경보를 즉시 구분하기 어렵습니다.
- 실종자의 사진을 확인하려면 별도의 링크에 접속해야 합니다.
- 이름과 긴 문장 중심으로 전달되어 인상착의를 기억하기 어렵습니다.
- 실종자를 발견했을 때 제보 방법을 바로 찾기 어렵습니다.
- 실종자의 발견 여부와 경보 종료 상태를 지속적으로 확인하기 어렵습니다.

Missing Alert Care는 사용자가 앱을 직접 열어 정보를 검색하기 전에, **알림이 도착하는 순간부터 실종경보임을 명확하게 인식하도록 만드는 것**에 집중합니다.

## 핵심 기능

### 1. 실종경보 전용 푸시 알림

- 일반 안전안내와 구분되는 제목, 아이콘 및 알림 디자인
- 실종자 사진과 핵심 인상착의 표시
- 마지막 목격 장소 및 실종 시각 안내
- 알림 선택 시 실종자 상세화면으로 이동

### 2. 핵심정보 중심의 경보 화면

- 실종자 사진
- 이름 및 나이
- 옷차림
- 신체 특징
- 마지막 목격 장소
- 실종 시각
- 현재 수색 상태

### 3. 신속한 제보 연결

- 실종아동찾기센터 182 전화 연결
- 목격 제보 안내
- 목격 장소와 시간 기록 지원
- 안전한 제보 방법 안내

### 4. 경보 상태 관리

- 수색 중
- 정보 갱신
- 발견 완료
- 경보 종료

동일한 실종자에 대한 정보를 하나의 사건으로 관리하여 최신 상태를 쉽게 확인할 수 있도록 구성합니다.

## 서비스 흐름

```
실종경보 발령
      ↓
경찰청 실종경보정보 수집
      ↓
백엔드에서 신규 경보 확인
      ↓
Firebase 실종경보 전용 푸시 전송
      ↓
사용자가 사진·옷차림·목격 장소 확인
      ↓
목격 시 182 전화 또는 제보
```

## 활용 데이터

### 경찰청 실종경보정보 서비스

안전Dream에서 제공하는 실종경보 발령 정보를 활용합니다.

주요 활용 항목은 다음과 같습니다.

- 대상자 구분
- 이름 및 성별
- 실종자 사진
- 신체 특징
- 실종 관련 정보
- 경보 발령 상태

공공데이터포털:

https://www.data.go.kr/data/3051810/openapi.do

### 행정안전부 긴급재난문자 API

전체 재난문자와 실종경보의 전달 방식을 비교하거나 향후 서비스 범위를 확장할 때 활용할 예정입니다.

공공데이터포털:

https://www.data.go.kr/data/15134001/openapi.do

## 폴더 구조

현재 저장소에는 소개 페이지와 공통 설정 파일만 있습니다. 앱·서버·가상 데이터 폴더는 각 기능 브랜치가 머지되면 추가될 **예정**입니다.

### 현재

```
missing-alert-care/
├── index.html      # 기억해줘 웹 서비스 페이지
├── about.html      # 프로젝트 소개 페이지
├── .env.example    # 환경변수 예시 (실제 키는 .env에 작성하며 Git에 올리지 않음)
├── .gitignore
└── README.md
```

### 권장 구조 (예정)

```
missing-alert-care/
├── mobile/         # (예정) Flutter 앱
├── backend/        # (예정) FastAPI 서버
└── sample-data/    # (예정) 개발·시연용 가상 실종경보 데이터
```

- 폴더 이름은 위 세 가지(`mobile/`, `backend/`, `sample-data/`)로 통일합니다.
- `sample-data/`에는 가상의 인물과 데이터만 넣고, 실제 개인정보나 실제 API 응답은 넣지 않습니다.

## 개인정보 및 안전 원칙

실종자 정보는 민감한 개인정보이므로 다음 원칙을 준수합니다.

- 공식적으로 공개가 허용된 정보만 활용합니다.
- 개발 및 시연 단계에서는 가상의 인물과 데이터를 사용합니다.
- 발견 완료 시 실종자의 개인정보 노출을 최소화합니다.
- 목격자의 위치와 개인정보를 다른 사용자에게 공개하지 않습니다.
- 확인되지 않은 시민 제보를 공개 지도에 표시하지 않습니다.
- 얼굴 인식과 실종자 자동 판별 기능은 사용하지 않습니다.
- API 인증키와 Firebase 관리자 인증정보는 공개 저장소에 업로드하지 않습니다.

## 기술적 한계와 확장 방향

일반 애플리케이션은 정부가 발송하는 기존 재난문자의 시스템 디자인을 직접 변경할 수 없습니다.

따라서 MVP에서는 경찰청 실종경보정보를 기반으로 별도의 푸시 알림을 제공하며, 향후 경찰청·지자체·스마트폰 제조사와의 연계를 통해 실종경보 전용 알림 체계로 확장하는 것을 목표로 합니다.

향후 다음 기능을 추가할 수 있습니다.

- 사용자 관심 지역 기반 알림
- 마지막 목격 장소 지도 표시
- 다국어 실종경보 안내
- 고령자 및 저시력자를 위한 접근성 모드
- 동일 사건의 중복 경보 통합
- 실종경보 발령부터 발견 완료까지의 타임라인
- 경보 디자인에 따른 사용자 기억률 분석
