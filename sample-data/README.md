# sample-data

> [!WARNING]
> **이 폴더의 모든 파일은 개발·시연·AI 평가용 가상 데이터입니다.**
> 등장하는 인물, 실종 사건, 재난문자는 모두 지어낸 것이며 실제 인물·사건과 관련이 없습니다.

## 파일

| 파일 | 형식 | 내용 |
|---|---|---|
| `missing-alerts.json` | 안전Dream 실종경보 API(`amberList.do`) 응답 | 가상 실종자 6명 |
| `disaster-messages.json` | 행정안전부 긴급재난문자 API(`DSSP-IF-00247`) 응답 | 가상 문자 45건 (실종 35건, 실종 아닌 문자 10건) |
| `disaster-messages-labels.json` | 자체 형식 | `disaster-messages.json`의 정답. AI 옷차림 추출 정확도 평가용 |
| `disaster-messages-eval.json` | 행정안전부 긴급재난문자 API 응답 | 평가용 가상 문자 30건 (모두 실종 문자) |
| `disaster-messages-eval-labels.json` | 자체 형식 | `disaster-messages-eval.json`의 정답 |

### missing-alerts.json

- 실제 API와 필드 이름, 값의 타입이 같습니다. 예를 들어 `age`는 숫자, `ageNow`는 문자열입니다.
- 대상구분 코드(`writngTrgetDscd`)는 실제 응답에 나오는 5가지(`010`, `060`, `061`, `062`, `070`)를 모두 넣었습니다.
- `occrAdres`는 실제 응답처럼 끝에 공백이 한 칸 있습니다. 화면에 쓸 때는 앞뒤 공백을 지워야 합니다.

### disaster-messages.json

- 실제 API와 최상위 키(`header`, `numOfRows`, `pageNo`, `totalCount`, `body`), 필드 이름, 날짜 형식이 같습니다.
- 실종 문자의 재난구분(`DST_SE_NM`)은 실제처럼 "기타"입니다. 실제 API에는 "실종" 구분이 따로 없기 때문입니다.
- 실종 문자 35건 중 6건은 `missing-alerts.json`의 6명과 같은 사람입니다. 이름, 성별, 나이, 키, 몸무게, 실종 동이 같습니다.
- 문자를 읽기 어렵게 만드는 표현을 일부러 섞었습니다.
  - 띄어쓰기 없는 붙여 쓰기
  - 안경미착용 같은 부정 표현
  - 곤색, 네이비처럼 같은 색을 다르게 쓴 표현
  - 항목 순서가 뒤섞인 문장
  - 옷 정보가 아예 없는 문장
  - 신고 번호 112와 182

### disaster-messages-labels.json

- `labels`: `SN`마다 실종 문자인지, 이름, 성별, 나이, 키, 몸무게, 실종 장소, 옷차림(부위·종류·색), 착용하지 않은 항목, 특이사항, 신고 번호, 연결된 안전Dream 식별번호(`linked_msspsnIdntfccd`), 어려운 표현 종류(`hard_cases`)를 담습니다.
- `color_rule`: 색을 하나로 모으는 규칙입니다.
  - `color`는 표준색, `color_text`는 문자에 적힌 그대로의 표현입니다.
  - 곤색, 네이비, 남색은 "남색"으로 모으고, 청색은 남색과 다른 색으로 둡니다.

### disaster-messages-eval.json / disaster-messages-eval-labels.json (평가용)

- **규칙 추출기를 만든 사람이 보지 않은 표현으로 팀원 두 명이 따로 쓴 문자 30건**입니다(각 15건, `SN` 9910001~9910015, 9910016~9910030). `disaster-messages.json`은 규칙 단어 목록과 같은 사람이 만들어서 규칙이 100%가 나오므로, "규칙 vs AI" 비교는 이 파일로 합니다.
- **규칙 추출기(`backend/ai/extract_rule.py`)를 이 파일의 표현에 맞춰 고치지 마세요.** 고치면 평가가 다시 의미 없어집니다. 규칙을 고치고 싶으면 새 평가용 문자를 따로 만들어 그걸로 평가해야 합니다.
- 들어 있는 표현:
  - 실제 경찰청 문자 형식(`[○○경찰청] … vo.la/… / ☎182`), 상황 설명 문장, 슬래시로 나눈 형식(`/이름/남/85/…`)
  - 실종 표현의 변형("귀가 안 하심", "미귀가", "연락안됨", "찾고 있습니다" 등 "실종·찾습니다"가 없는 문장)
  - 오타(잠퍼·운동하·가디간·슬렉스·샌달), 줄임말(츄리닝·쓰레빠·반팔·위아래·폰·조거·몸빼)
  - 영어 색 이름(그레이·블랙·화이트·아이보리), 붙여 쓰기, 겹쳐 입음, 원피스 같은 일체형 옷
  - 여러 형태의 부정 표현("모자 안 씀", "안경은 안 쓰심", "보청기 안끼고", "모자X 가방X")과 착용 긍정("안경씀", "마스크 착용")
  - 옷 정보 없음("착의 불상"), 보조기구만 있는 문장
- 파일 구조는 `disaster-messages.json`, `disaster-messages-labels.json`과 같습니다.
- 정답 작성 기준:
  - "정보 없음"과 "없음"은 빈 값입니다.
  - "색 정보 없음"인 옷은 종류만 넣고 `color`·`color_text`를 비웁니다. 평가에서 그 칸은 색 채점에서 빼고, 결과에 색을 지어 넣으면 환각으로 셉니다.
  - 괄호 설명(고무 샌들, 나이키)은 빼고 핵심 단어만 넣었습니다.
  - 표준색에 없는 색은 가장 가까운 표준색으로 넣었습니다: 와인색 → 자주색, 아이보리 → 베이지색, 연두 → 초록색, 살색 → 베이지색(밤색은 원래 표준표에서 갈색). 적힌 표현은 `color_text`에 그대로 있습니다.
  - 착용한 안경·모자·마스크는 소지품(`accessories`), 착용하지 않은 것("모자X 가방X", "보청기 안끼고", "안경미착용")은 `not_wearing`(평가에서는 `negatives`)입니다.
  - 겹쳐 입은 상의(3·11·15번)는 바깥 옷을 먼저 적었습니다. 출력 형식의 `upper` 칸은 하나라서 평가에는 바깥 옷만 쓰입니다.
  - 원피스(30번)는 `upper`에 넣고 `lower`에는 스타킹만 넣었습니다.
  - "츄리닝 차림"(17번)처럼 위아래 한 벌로 적힌 것은 `트레이닝 상의`·`트레이닝 바지`로 나눠 넣었습니다(6번 "위아래 검정츄리닝"과 같은 기준).
  - 지팡이·보행보조기는 기존 정답 파일처럼 특이사항(`features`)에 두었고, 평가할 때 소지품으로 바뀝니다.
- `hard_cases`에 특이 표현 종류를 적었습니다: 오타, 줄임말, 영어색, 붙여쓰기, 겹쳐입음, 부정표현, 옷없음, 실제형식, 실종표현변형, 슬래시구분, 부정기호, 착용긍정, 일체형, 보조기구만.
- 가상 이름이 기존 45건·실종경보 6명·이 파일 안에서 겹치지 않도록 6명을 바꿨습니다(9번 구가상, 11번 나예시, 16번 도샘플, 17번 마더미, 22번 변가명, 27번 석연습). 문자 안의 이름도 같이 바꿨습니다.
- 수신지역 ID가 실제 데이터에서 구 단위로 확인되지 않은 곳(수원 영통구, 성남 분당구, 용인 수지구, 부천)은 시도 단위 `경기도`(ID 21)로 넣었습니다.

실행: `python -m backend.ai.run_eval --mode rule --dataset eval`

## 가상 데이터임을 알아보는 방법

| 항목 | 규칙 |
|---|---|
| 이름 | 김가상, 이예시, 박샘플, 최테스트, 정모의, 한더미처럼 가상임이 바로 드러나는 이름 |
| 실종자 식별번호 (`msspsnIdntfccd`) | `9990001`부터 |
| 문자 일련번호 (`SN`) | `9900001`부터, 평가용은 `9910001`부터 |
| 사진 | 없음 (`tknphotoFile` 빈 값, `tknphotolength` 0) |
| 지역 | 실제 동 이름을 쓰지만, "내 위치 주변 알림" 기능을 시연하기 위해 정한 위치일 뿐 실제 사건과 관련이 없습니다. 도로명 주소와 건물 이름은 쓰지 않았습니다. |

## 주석 필드를 넣지 않은 이유

`missing-alerts.json`, `disaster-messages.json`, `disaster-messages-eval.json`에는 `_comment` 같은 설명용 필드를 넣지 않았습니다. 실제 API 응답과 형식을 똑같이 유지해야, 나중에 실제 API로 바꿀 때 앱과 서버 코드를 고치지 않아도 되기 때문입니다. 설명은 이 README에 둡니다.

정답 파일(`disaster-messages-labels.json`, `disaster-messages-eval-labels.json`)은 API 응답이 아니라 평가용 자체 형식이라서, 색 규칙(`color_rule`)을 파일 안에 함께 적었습니다.

## 시연할 때 주의할 점

시연 화면, 발표 자료, 시연 영상에는 **"가상 데이터"라는 표시를 반드시 함께 보여 주세요.** 실종경보는 실제처럼 보이기 쉬워서, 표시가 없으면 보는 사람이 실제 사건으로 오해할 수 있습니다.
